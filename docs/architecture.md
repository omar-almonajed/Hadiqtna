# معمارية منصة حديقتنا | Hadiqtna System Architecture

## 1. نظرة عامة على النظام
منصة **حديقتنا (Hadiqtna)** هي نظام متكامل لإدارة ومراقبة الحدائق العامة والحاويات الذكية عبر إنترنت الأشياء (IoT). يهدف النظام التجريبي الأولي إلى مراقبة حديقة عامة واحدة (**حديقة النخيل العامة**) وحاوية ذكية مزودة بلوحة **ESP32** وحساس مسافة فوق صوتي ومؤشرات **LED**، بالإضافة إلى بوابة لبلاغات المواطنين وسير عمل للصيانة الميدانية.

> **توضيح تشغيلي مهم**: المنصة تراقب وترصد وتنظم العمل وتدعم فرق الصيانة والنظافة بالتنبيهات والبيانات، بينما يقوم الموظفون والفنيون بعمليات التفريغ والإصلاح الفعلي ميدانياً.

---

## 2. مسار تدفق البيانات (End-to-End Architecture)

```text
[Ultrasonic Sensor (HC-SR04 / JSN-SR04T)]
        │  نبضات مسافة بالسم + تصفية الوسيط
        ▼
[ESP32 Microcontroller] ──► [LEDs: أخضر / أصفر / أحمر]
        │  Wi-Fi + HTTPS POST + Bearer Device Token
        ▼
[Node.js / Express Backend REST API]
        │  مصادقة الجهاز + منع التكرار + التحقق الفيزيائي + حساب النسبة + محرك التنبيهات
        ▼
[Cloud Firestore Database]
        │  تحديث لحظي عبر onSnapshot و SSE
        ▼
[React + TypeScript RTL Web Dashboard]
```

### مسار بلاغات المواطنين والصيانة
`الزائر (/citizen)` ➔ `POST /api/reports (تحقق وحفظ الصورة)` ➔ `Cloud Firestore` ➔ `لوحة المشرف (/reports)` ➔ `تحويل إلى مهمة صيانة (/maintenance)` ➔ `فني الصيانة (تنفيذ وتوثيق)`

## 3. مكونات الواجهة الأمامية (Frontend)
- مبنية بـ **React 19 + TypeScript + Vite + Tailwind CSS v4** مع دعم أصيل للغة العربية واتجاه **RTL** وخيار التبديل إلى الإنجليزية.
- تستخدم **React Router** لتوجيه المسارات العامة (`/`, `/login`, `/citizen`) والمسارات المحمية حسب الصلاحية (`/dashboard`, `/bins`, `/bins/:binId`, `/devices`, `/monitoring`, `/alerts`, `/reports`, `/maintenance`, `/parks`, `/analytics`, `/settings`).
- تعتمد على **Firebase Authentication (Google Sign-In)** للحصول على `ID Token` حقيقي يُمرر في ترويسة `Authorization: Bearer` لجميع طلبات الخادم.
- تستخدم **Recharts** لعرض الاتجاهات التاريخية واللحظية الحقيقية فقط، وتعرض حالات فارغة واضحة عند عدم كفاية البيانات.

---

## 4. مكونات الخادم الخلفي (Backend)
- مبني بـ **Node.js + Express + TypeScript** (`server.ts` + `server/`).
- يمثل **السلطة الموثوقة الوحيدة** (Trusted Authority) لقبول قراءات العتاد، التحقق من رموز الأجهزة، حساب نسب الامتلاء، توليد التنبيهات، وتطبيق قواعد الصلاحيات (`ADMIN`, `SUPERVISOR`, `WORKER`).
- يوفّر طبقة حماية شاملة تشمل: `helmet`، قيود `CORS`، تحديد معدل الطلبات (`express-rate-limit`)، التحقق الصارم عبر `Zod`، وحماية رفع الصور بفحص البصمة الثنائية (Magic Bytes).

---

## 5. الفصل بين وضع المحاكاة (DEMO) ووضع العتاد (HARDWARE)
- **DEMO Mode**: يتيح للمشرفين والمدراء اختبار كامل دورة العمل (45% ➔ 79% ➔ 80% ➔ 95% ➔ تفريغ) وتجربة انقطاع الجهاز دون عتاد مادي. تحمل كل قراءة وتنبيه في هذا الوضع وسم `DEMO` بوضوح.
- **HARDWARE Mode**: يعطل المحاكي ويستقبل القراءات الفعلية من جهاز **ESP32** فقط عبر `/api/iot/readings` بوسم `HARDWARE` دون أي مؤقتات وهمية في الواجهة.
- التبديل بين الوضعين لا يحذف أو يفسد السجلات التاريخية.
